화면 1 — 내역서 업로드 및 공종명 자동 매핑

샘플 내역서 24행 중 22행 자동 확정. "아스팔트 커팅(m)"은 표준품셈 단위(m²)와 달라 미매칭으로 분리되고, "현장 정리(식)"은 생산성 기준이 없어 제외됩니다. 이렇게 애매한 것을 자동으로 확정하지 않는 것이 설계 원칙입니다.
행을 클릭하면 후보 3개와 신뢰도, 매핑 근거(동의어 일치·단위 불일치 등)를 보고 실무자가 확정합니다. 확정한 표기는 다음 내역서부터 자동 매핑됩니다.

화면 2 — 작업일수 산정

공종별로 적용 표준품셈 항목·생산성·조 편성·근거 조항이 함께 표시됩니다. 투입조 수를 바꾸면 공정표와 보고서까지 즉시 다시 계산됩니다.

화면 3 — 기상 데이터 분석 및 비작업일수

기상청 대구(143) 지점 2016~2025 실데이터(공공데이터포털 API)로 계산한 월별 10년 평균 비작업일수. 기준별(강수·폭염·강풍·적설)로 쌓아 표시. 같은 날 두 기준이 겹치면 1일로만 세고, 휴일과 겹친 날은 제외합니다. 우측 룰 엔진의 값을 바꾸면 즉시 재계산됩니다.

화면 4 — 공정표 및 주공정선(CPM)

주황 막대가 주공정선(여유 0일), 빗금이 여유일수입니다. 우측 달력 환산에서 휴일·기상 비작업일을 건너뛴 실제 착공~준공 일정을 확인합니다.

화면 5 — 검토 보고서 초안

계획 공기 180일 대비 산정 190일 → "검토 필요" 판정. 모든 수치 옆에 산정 근거가 붙어 있고, 서술 문장 영역은 "AI 초안 · 검토자 확인 필요"로 구분해 표시합니다.

화면 6 — 설정 (기준값 분리)

매핑 임계값, 간접일수, 보정률, 준비·정리기간, 작업 제한 룰을 코드 수정 없이 조정합니다. 유지보수 우려에 대한 답입니다.

6완료 기준 · 진행 확인 · 유지보수

성공적 완료의 기준 (제안)

  1. 귀사가 제공한 실제 내역서 3건 이상이 업로드부터 보고서 초안까지 오류 없이 끝난다
  2. 자동 매핑이 못 잡은 공종은 반드시 "검토 필요·미매칭"으로 드러나고, 실무자가 화면에서 보정할 수 있다 (틀린 것을 맞다고 하지 않는 것이 핵심)
  3. 보고서의 모든 수치 옆에 표준품셈 항목·기상 기준·계산식 근거가 붙는다
  4. 비작업일수 결과가 귀사가 지금 손으로 계산한 값과 같은 기준에서 일치한다 (검산 표 제출)
  5. 기준값(임계값·보정률·기간)을 개발자 없이 설정 화면에서 바꿀 수 있다

진행 상황 확인 방법

  • 2주 단위 동작 화면 시연 — 온라인 화면 공유 또는 대구 방문(협의). 문서가 아니라 실제로 돌아가는 화면으로 확인
  • 항상 접속 가능한 검토용 주소 — 개발 중인 최신 버전을 언제든 열어볼 수 있는 URL 제공
  • 주간 진행 요약 — 완료·진행·다음 주 계획·확인 요청 사항을 한 장으로
  • 확인 요청 목록 — 판단이 필요한 항목은 모아서 한 번에 질의 (실무 담당자 부담 최소화)

유지보수와 인수인계

인수인계 범위
  • 전체 소스코드 (발주사 소유 저장소)
  • DB 스키마 + 표준품셈·공종 매핑 기준 데이터
  • 요구사항 정의서 · 화면 설계서
  • 배포·운영 매뉴얼 (한 번의 명령으로 재설치 가능)
  • 기준값 설정 가이드 (비개발자용)
다른 업체가 이어받을 수 있는 구조
  • 널리 쓰이는 표준 기술만 사용 (특수 프레임워크 없음)
  • 산정 규칙은 설정·데이터로 분리, 코드에 숨기지 않음
  • API 명세 문서 자동 생성 (FastAPI 기본 기능)
  • 납품 후 하자보수 기간 무상, 이후 월 단위 유지보수 또는 건별 협의

7미팅 시연 순서 (약 10분)

1
내역서 업로드 (1분)샘플 xlsx를 끌어다 놓고 24행이 표로 바뀌는 것을 보여드립니다. 가능하면 귀사 내역서를 그 자리에서 올립니다.
포인트: 양식이 달라도 헤더 행을 스스로 찾는다
2
공종명 매핑 (2분)흙깎기·토사절취가 둘 다 "절토"로 잡힌 것, "아스팔트 커팅"이 단위 불일치로 미매칭된 것을 짚고, 행을 클릭해 후보에서 직접 확정합니다.
포인트: 애매한 것은 자동 확정하지 않고 실무자에게 넘긴다. 실연동이면 "AI 문맥 보정 실행"을 먼저 눌러 두고(30~60초) 설명하는 동안 결과가 갱신되게 한다
3
작업일수 (1분)유로폼 투입조를 4 → 2로 바꿔 순작업일수가 11 → 22일로 늘고 공정표·보고서까지 따라 바뀌는 것을 보여드립니다.
4
기상·비작업일수 (2분)강수 기준을 3mm → 10mm로 바꾸면 연평균 비작업일이 약 64 → 46일로 줄어드는 것, 7·8월에 폭염 기준이 쌓이는 것, 휴일 중복 제외 토글을 보여드립니다.
포인트: 기준은 설정값이라 국토부 기준이 바뀌어도 개발 없이 대응
5
공정표 (2분)주공정선을 짚고, 막대를 클릭해 "되메우기" 선행에 "조적공사"를 추가하면 총 작업일이 128 → 136일로 늘고 주공정선이 조적공사를 지나도록 바뀌는 것을 보여드립니다. 달력 환산에서 휴일·기상일이 건너뛰어지는 것을 확인합니다.
6
검토보고서 (2분)계획 180일 vs 산정 190일 "검토 필요" 판정 → 2단계 화면에서 토공·철근 투입조를 늘리면 "적정"으로 바뀌는 것을 보여드리고, PDF 저장을 실행합니다.
포인트: 수치는 전부 계산값, 문장만 AI 초안. 실연동이면 "AI 서술 초안 생성"을 눌러 3개 문단이 채워지는 것을 보여준다(20~40초)
7
데모 범위 안내 + 질의 (나머지)데모와 실 시스템의 차이를 화면으로 보여드리고, 8절의 확인 사항을 질의합니다.

8착수 전 확인 요청 사항

#확인 항목왜 필요한가
1표준품셈 자료의 형태 (PDF/엑셀, 연도판, 건축·토목 범위)정제 DB 구축 공수와 매핑 정확도를 좌우하는 1순위 변수
2지금 손으로 작성한 검토보고서 샘플 2~3건 (내역서 + 완성 보고서 쌍)완료 기준 4번 "검산"의 정답지. 보고서 양식·문장 톤의 기준
3비작업일수 산정에 실제로 쓰는 기준 (강수 3mm 외 풍속·적설·한파 적용 여부, 공종별 차등 여부)룰 엔진 초기값 확정
4간접·보정일수 산정 방식 (검측·양생 일수, 도심지·소규모 보정 근거 문서)현재 데모는 일반적 가정값. 귀사 기준으로 교체 필요
5공정 선후행 관계를 누가 정하는가 (표준 템플릿 vs 건별 입력)CPM 자동화 범위 결정
6서버 환경 (클라우드 신규 / 기존 서버 / 사내) 및 공공데이터포털 계정인프라 구축·배포 항목
7보고서 최종 출력 형식 (PDF / DOCX / HWP)HWP는 별도 변환 경로가 필요해 범위 확정 필요
8"나머지 업무"의 대략적 목록1차 설계에서 확장 여지를 미리 남기기 위함
