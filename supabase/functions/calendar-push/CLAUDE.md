# 사내 캘린더 알림·근무지 규칙 (Claude용)

이 함수(`calendar-push`)와 화면(`dashboard/src/calendar.jsx`)은 **같은 근무지 규칙**을 따로 구현한다. 한쪽을 바꾸면 다른 쪽도 같이 바꾸고, `plan.test.ts`와 `tools/calendar-qa/`(QA 환경·점검)로 확인한다.

## 근무지 규칙
- 우선순위: 종일 휴가 > 직접 고른 개인 근무지 > 대면 미팅 외근 > 팀 근무지(그날만 정한 것 > 주간 패턴).
- 대면 미팅 외근(캘린더 미팅 '외근 표시' · 위시켓 대면 미팅): **시간 있는 미팅은 시작 시각부터 외근, 그 전엔 팀 근무지**(출근 인원에 포함, '시청역 · 14:00 외근'). 종일 미팅만 하루 전체 외근. 여러 건이면 종일 우선, 아니면 가장 이른 시각.
- 반차는 근무지를 유지하고 반차를 붙여 표시. 직접 고른 근무지가 팀 근무지와 같으면 예외가 아니다.
- 그날만 정한 팀 근무지는 '이날만'이 아니라 **'평소 ○○'**(주간 패턴의 그 요일 근무지)로 표시. 평소와 같은 곳이면 표시하지 않음.

## 알림 (2026-11-03 사용자 결정)
- 미팅 시작 전 알림은 없다. 시간·빈도 선택 설정은 만들지 않는다(유연출퇴근 — 기본값으로 해결). 켜기/끄기 두 개만.
- **다음 근무일 안내**: 근무일 16:00~17:30 첫 실행(가장 이른 퇴근 전). 조건 — 팀 근무지 변동 · 내 근무지 다름 · 내 일정 · 팀원 상태가 평소와 다르고 **오늘과도 다름**(같은 휴가가 이어지면 다시 안 보냄). 다음 근무일 종일 휴가인 사람은 제외.
- **변경 알림**: 팀 근무지·팀원 개인 근무지·휴가·미팅 외근은 오늘~다음 근무일 → 바꾼 사람 뺀 전원. 주간 패턴(8일 안에 실제로 쓰임, 내용이 바뀐 경우만) → 전원. 일정(7일 안 회차) → 참석자(전·후). 밤 22:00~07:30 은 아침으로 미룸.
- 같은 대상을 한 실행 안에서 여러 번 바꾸면 처음·끝만 비교(지웠다 되돌림은 안 보냄). 반복 일정 나누기 짝은 같은 사람·15초 이내로 판단(감사 번호 차이 금지 — 다른 표 기록이 끼어든다).
- 같은 실행의 안내를 받는 사람에게, 다음 근무일에 대한 **16:00 전** 변경 알림은 생략(안내에 담김). 16:00 이후 변경은 보냄 — 알림이 빠지는 쪽으로 줄이지 않는다.

## 알림 문구 원칙
- 제목 = 누가/무엇이 어떻게(바뀐 곳·일정 이름 포함). 본문 = 언제 · 바뀐 것 · 이유 · 바꾼 사람(당사자와 다를 때만, 동사 맞춤: 추가/변경/취소).
- 쓰지 않는다: 제목을 본문에서 반복, 보내는 규칙 설명('(평소와 다름)'·'(계속)'), 다 나열하면서 붙이는 건수, '패스트파이브'·'재택근무'의 '근무', '— 누군가', 제목에 날짜가 있을 때 본문 날짜.
- 아침에 갈 곳이 먼저: 오후 미팅이 있는 날 본인 안내 제목은 '🏢 내일 시청역2호점 · 14:00 외근 (…)'.

## 운영
- 5분마다 pg_cron → 이 함수. 실행마다 `push_state.heartbeat` 기록 → `calendar_push_status()` RPC → 화면이 30분 넘게 끊기면 캘린더에 경고, 설정 창에 마지막 실행 표시.
- 발송 실패(5xx 등)는 `push_state.retry_queue` 에서 최대 6번 재시도. 404/410 이면 구독 삭제.
- 클라이언트는 `push_subscriptions` 에서 알림 켜기/끄기 두 칸만 고칠 수 있다(등록·이전은 `register_push_subscription` RPC).
- 배포: 함수는 `supabase functions deploy calendar-push`(verify_jwt 유지), 테스트는 `deno test plan.test.ts`.
