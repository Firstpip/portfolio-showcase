# 🔀 모드: workflow-diagram (노코드·SaaS 연동 공고 폴백)

이 공고는 **여러 서비스를 연결하는 자동화**가 핵심이다 (노션·슬랙·구글시트·메일 등). 연동 자체는 데모로 만들 수 없으니, **워크플로우가 어떻게 흐르는지 시각적으로 보여주고 한 번 돌려보게** 한다.

보는 사람이 얻어야 할 인상: "우리 업무 흐름을 정확히 이해했고, 어디를 자동화하는지 안다."

## 화면 구성 (이 순서를 지켜라)

1. **워크플로우 다이어그램** — 트리거 → 처리 단계들 → 결과. 각 단계는 카드, 사이는 화살표.
   - 세로 스택으로 그리고 단계 사이에 `↓` 를 둔다. 가로 배치는 폭이 좁아지면 깨진다.
   - 각 카드에 아이콘(lucide) + 서비스명 + 한 줄 설명 + 상태 배지.
2. **"실행해 보기" 버튼** — 누르면 단계가 **위에서 아래로 순차 점등**된다. 단계마다 0.6~1.2초 지연을 주고 대기→진행중→완료로 상태를 바꾼다. 마지막에 결과 요약.
3. **실행 이력** — 시드 기반 목록. 시각·트리거·결과·소요시간.
4. **연결된 서비스 목록** — 공고에 나온 서비스들을 카드로. 각 카드에 "연결됨" 배지와 마지막 동기화 시각.

## 반드시 지킬 것

- **순차 점등이 이 모드의 핵심이다.** 이게 없으면 그냥 정적인 그림이라 아무 인상도 못 준다. `setTimeout` 체인이나 async 루프로 단계 상태를 하나씩 바꿔라.
- 실행 중에는 버튼을 비활성화하고, 끝나면 "다시 실행" 으로 되돌린다.
- 단계는 4~7개. 너무 잘게 쪼개면 읽히지 않는다.
- 실패 분기도 하나 보여주면 좋다 (예: 3번째 단계에서 조건 불충족 → 대체 경로).

## 다이어그램 그리는 법

- **다이어그램 라이브러리를 import 하지 마라.** mermaid·reactflow·d3 등은 런타임에 없다 — 빌드가 깨진다.
- 순수 HTML + Tailwind 로 충분하다: 카드 `div` 를 세로로 쌓고, 사이에 `↓` 문자나 얇은 세로선 `div` 를 둔다. 분기는 들여쓰기와 좌측 보더로 표현한다.
- 아이콘은 이번 스택의 lucide 패키지만 사용한다.

## 하면 안 되는 것

- 실제 외부 서비스 호출·OAuth 흐름
- 노코드 도구(Zapier·Make 등) 화면을 흉내 내는 것 — 우리가 만든 시스템처럼 보여야 한다
- 드래그앤드롭 편집기 (구현 비용 대비 시연 가치가 낮다)
